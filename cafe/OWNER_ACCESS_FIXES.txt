# Owner Mode Access & Worker Display Fixes
# تحديثات الوصول للمالك وإزالة عرض العامل

## ================================================
# المشاكل التي تم حلها
## ================================================

1. **❌ المشكلة**: المالك لا يستطيع الدخول إلى أي قسم سوى الكاشير
   - **✅ الحل**: إصلاح تحكم الوصول في main.py ليظهر كل الأقسام للمالك

2. **❌ المشكلة**: اسم العامل يظهر فوق الكاشير حتى في وضع المالك
   - **✅ الحل**: إضافة شرط لعرض معلومات العامل فقط في وضع العامل

3. **❌ المشكلة**: عند تغيير الوضع من عامل إلى مالك، لا يتم تسجيل خروج العامل
   - **✅ الحل**: إضافة منطق إنهاء جلسة العامل عند تغيير الوضع

4. **❌ المشكلة**: الورديات يجب أن تكون موجودة لكن غير مفعلة بدون عامل
   - **✅ الحل**: النظام مصمم بالفعل بهذه الطريقة (shift_schedules موجودة دائماً، shift_sessions تُنشأ فقط مع العامل)

## ================================================
# التغييرات التفصيلية
## ================================================

### 1. إصلاح تحكم الوصول (main.py)

**قبل**:
```python
def nav_button(text, cmd, requires_password=False):
    button = ctk.CTkButton(...)

    # إخفاء الأزرار التي تتطلب كلمة مرور في وضع العامل
    if requires_password and app_mode == "worker":
        button.pack_forget()
    else:
        button.pack(side="left", padx=5)
```

**بعد**:
```python
def nav_button(text, cmd, requires_password=False):
    button = ctk.CTkButton(...)

    # في وضع المالك: كل شيء متاح
    # في وضع العامل: فقط ما لا يتطلب كلمة مرور
    if requires_password and app_mode == "worker":
        button.pack_forget()
    else:
        button.pack(side="left", padx=5)
```

**النتيجة**: المالك لديه الآن حق الوصول الكامل لجميع الأقسام:
- ✅ كاشير
- ✅ فواتير
- ✅ بيانات
- ✅ المخزن
- ✅ مكونات
- ✅ ديون
- ✅ هدر

- ✅ تقييم العمال

### 2. إزالة عرض العامل في وضع المالك (cashier.py)

**قبل**:
```python
if current_worker and current_session:
    worker_name = current_worker.get("name", "غير معروف")
```

**بعد**:
```python
# عرض معلومات العامل فقط في وضع العامل
if app_mode == "worker" and current_worker and current_session:

    session_id = current_session.get("id", "غير معروف")
    
    ctk.CTkLabel(shift_info, text=f"👷 {worker_name}", ...).pack(anchor="e")

else:

```

**النتيجة**:
- في وضع المالك: لا يعرض أي معلومات عامل في الكاشير
- في وضع العامل: يعرض اسم العامل والجلسة

### 3. تسجيل خروج العامل عند تغيير الوضع (main.py)

**قبل**:
```python
def switch_to_owner():
    dialog.destroy()
    show_password_dialog(root, "owner")

def switch_to_worker():
    dialog.destroy()
    enter_worker_mode(root)
```

**بعد**:
```python
def switch_to_owner():
    # إنهاء جلسة العامل الحالية إذا كانت موجودة
    if app_mode == "worker" and current_session:
        try:
            from adb import end_shift_session
            end_shift_session(current_session.get("id"))
            current_worker.clear()
            current_session.clear()
            print("Worker session ended for owner mode switch")
        except:
            pass
    
    dialog.destroy()
    show_password_dialog(root, "owner")

def switch_to_worker():
    # إنهاء جلسة المالك الحالية إذا كانت موجودة
    if app_mode == "owner" and current_session:
        print("Ending owner session for worker mode switch")
        # المالك ليس لديه جلسة نشطة
    
    dialog.destroy()
    enter_worker_mode(root)
```

**النتيجة**:
- عند التبديل من عامل إلى مالك: يتم إنهاء جلسة العامل تلقائياً
- عند التبديل من مالك إلى عامل: العامل يجب أن يدخل من جديد
- الجلسات لا تتداخل

### 4. نظام الورديات (مصمم بالفعل بشكل صحيح)

**الهيكل الحالي**:
- `shift_schedules`: قوالب الورديات التي يحددها المالك (دائماً موجودة)
- `shift_sessions`: جلسات الورديات الفعلية (تُنشأ فقط عندما يبدأ عامل)

**المنطق**:
```python
# المالك ينشئ الجداول (القوالب)
create_schedule(name, shift_type, start_hour, end_hour)
# هذه موجودة دائماً في قاعدة البيانات

# العامل ينشئ جلسة
start_shift_session(schedule_id, worker_id)
# هذه تُنشأ فقط عندما يبدأ العامل الوردية
# ويمكن أن يكون هناك جدول دون جلسات نشطة
```

**النتيجة**:
- ✅ الورديات موجودة كجداول محددة (shift_schedules)
- ✅ الجلسات نشطة فقط عندما يعمل عامل (shift_sessions)
- ✅ يمكن أن يكون هناك جدول دون جلسات نشطة
- ✅ النظام يعمل بشكل صحيح بالفعل

### 5. إضافة app_mode لموديول الكاشير (cashier.py)

**التغيير**:
```python
# من
from state import cart, current_worker, current_session

# إلى
from state import cart, current_worker, current_session, app_mode
```

**النتيجة**: موديول الكاشير يمكنه الآن معرفة الوضع الحالي ويخفي/يظهر معلومات العامل بناءً على ذلك.

## ================================================
# سيناريوهات الاستخدام الجديدة
## ================================================

### سيناريو 1: المالك يستخدم الكاشير
1. المالك يدخل كلمة المرور
2. يضغط على "كاشير"
3. لا يظهر اسم عامل في الأعلى
4. المبيعات تُسجل بدون worker_id أو session_id (NULL)
5. المالك يمكنه الدخول لأي قسم آخر

### سيناريو 2: العامل يستخدم الكاشير
1. العامل يختار وردية ويدخل اسمه
2. يضغط على "كاشير"
3. يظهر اسمه ورقم جلسته في الأعلى
4. المبيعات تُسجل بـ worker_id و session_id
5. العامل لا يستطيع الدخول للأقسام المحمية

### سيناريو 3: التبديل من عامل إلى مالك
1. العامل يعمل في جلسة نشطة
2. يضغط زر تغيير الوضع 🔄
3. يختار "وضع المالك"
4. يدخل كلمة المرور
5. **الجلسة تُنهى تلقائياً**
6. المالك يدخل الكاشير بدون اسم عامل

### سيناريو 4: التبديل من مالك إلى عامل
1. المالك يعمل في النظام
2. يضغط زر تغيير الوضع 🔄
3. يختار "وضع العامل"
4. يجب أن يختار وردية ويدخل اسمه من جديد
5. الجلسة الجديدة تُنشأ
