def switch_to_owner():
    # إنهاء جلسة العامل الحالية فوراً إذا كانت موجودة
    if app_mode == "worker" and current_session:

#### switch_to_worker() - محسّن:

```python
def switch_to_worker():
    # التحقق والإنهاء في حالة وجود جلسة
    if app_mode == "owner" and current_session:
        print("⚠️  Owner doesn't have active sessions, clearing state")
        current_worker.clear()
        current_session.clear()
    elif app_mode == "worker" and current_session:
        # إذا كان في وضع عامل بالفعل، إنهاء الجلسة
        try:
            from adb import end_shift_session
            session_id = current_session.get("id")
            if session_id:
                end_shift_session(session_id)
                print(f"✅ Previous worker session {session_id} ended")
            current_worker.clear()
            current_session.clear()
        except Exception as e:
            print(f"Error ending previous session: {e}")
    
    dialog.destroy()
    enter_worker_mode(root)
```

# 3. شرح نظام worker_id
## ================================================

### هل worker_id آلي؟

**نعم، 100% آلي!**

### كيف يعمل:

#### في قاعدة البيانات:
```sql
CREATE TABLE workers (
    id INTEGER PRIMARY KEY AUTOINCREMENT,  -- <== مفتاح تلقائي
    name TEXT UNIQUE NOT NULL,
    ...
)
```

#### في الكود:
```python
def create_worker(name):
    cur.execute("INSERT INTO workers (name, active) VALUES (?, 1)", (name,))
    conn.commit()
    return cur.lastrowid  # <== ID يعاد تلقائياً
```

### دورة حياة worker_id:

```
1. إنشاء عامل:
   المالك يكتب: "علي"
   قاعدة البيانات تولد: worker_id = 1

2. اختيار وردية:
   علي يختار وردية
   worker_id = 1 يُربط بالجلسة

3. البيع:
   علي يبيع قهوة
   worker_id = 1 يُربط بالفاتورة

4. إنهاء الجلسة:
   الجلسة تُنهى
   worker_id = 1 يُحفظ في السجلات

5. العودة للعمل:
   علي يعود غداً
   worker_id = 1 (لا يتغير!)
   لكن session_id جديد
```

### أين يُستخدم worker_id:

✅ **shift_sessions**: ربط الجلسة بالعامل
✅ **receipts**: ربط كل فاتورة بالعامل
✅ **worker_ratings**: ربط التقييم بالعامل
✅ **analytics**: تحليل أداء العامل
✅ **state.py**: تتبع العامل النشط

### لماذا AUTOINCREMENT مهم:

1. **لا تعارضات**: كل عامل له ID فريد
2. **سهولة الربط**: كل شيء يُربط بـ worker_id
3. **الاستقرار**: ID لا يتغير أبداً
4. **الأتمتة**: لا تدخل يدوي
5. **سهولة التتبع**: سهل الاستعلام عن أي عامل

### كيف يعرف النظام worker_id:

عند دخول العامل:
```
1. العامل يختار اسمه من القائمة
2. النظام يعرف ID من جدول workers
3. worker_id يُمرر لـ start_shift_session()
4. worker_id يُحفظ في current_worker
5. كل فاتورة تستخدم current_worker["id"]
```
