# Worker ID System - Complete Explanation
# شرح كامل لنظام worker_id

## ================================================
# هل worker_id آلي؟
## ================================================

## نعم، worker_id آلي تماماً!

### كيف يعمل:

1. **في قاعدة البيانات (SQLite)**:
   ```sql
   CREATE TABLE IF NOT EXISTS workers (
       id INTEGER PRIMARY KEY AUTOINCREMENT,  -- <-- AUTOINCREMENT
       name TEXT UNIQUE NOT NULL,
       active BOOLEAN DEFAULT 1,
       rating REAL DEFAULT 0,
       total_ratings INTEGER DEFAULT 0,
       created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
   )
   ```

2. **عند إنشاء عامل جديد**:
   ```python
   def create_worker(name):
       cur.execute("INSERT INTO workers (name, active) VALUES (?, 1)", (name,))
       conn.commit()
       return cur.lastrowid  # <-- ID يعاد تلقائياً
   ```

3. **SQL يولد worker_id تلقائياً**:
   - أول عامل: worker_id = 1
   - ثاني عامل: worker_id = 2
   - ثالث عامل: worker_id = 3
   - ... وهكذا
   - لا حاجة لتدخل يدوي!

## ================================================
# دورة حياة worker_id
## ================================================

### 1. إنشاء العامل (المالك)
```
المالك يكتب: "علي"
النظام ينفذ: create_worker("علي")
قاعدة البيانات تُولد: worker_id = 1
```

### 2. العامل يختار وردية
```
علي يختار: "وردية صباحية"
النظام يعرف: worker_id = 1
النظام ينشئ: shift_session مع worker_id = 1
```

### 3. العامل يعمل ويبيع
```
علي يبيع: قهوة (5,000 ليرة)
النظام يربط: Receipt → worker_id = 1, session_id = 123
علي يبيع: عصير (3,000 ليرة)
النظام يربط: Receipt → worker_id = 1, session_id = 123
```

### 4. إنهاء الجلسة
```
علي ينهي الجلسة
الظ:
- worker_id = 1 في الجلسة
- إجمالي المبيعات
- يحسب التقييم الآلي
```

### 5. المستقبل
```
علي يعود للعمل
يختار وردية جديدة
worker_id لا يتغير = 1 دائماً
لكن session_id جديد في كل مرة
```

## ================================================
# التكامل الكامل في النظام
## ================================================

### أين يُستخدم worker_id:

#### 1. في sessions (shift_sessions):
```python
start_shift_session(schedule_id, worker_id)
# worker_id يُربط بالجلسة تلقائياً
```

#### 2. في receipts (الفواتير):
```python
INSERT INTO receipts (..., worker_id, session_id, ...)
VALUES (..., worker_id, session_id, ...)
# كل فاتورة تُربط بـ worker_id
```

#### 3. في ratings (التقييمات):
```python
add_worker_rating(worker_id, rating, notes, session_id, ...)
# التقييم يُربط بـ worker_id
```

#### 4. في analytics (التحليلات):
```python
SELECT * FROM receipts WHERE worker_id = ?
# تحليل أداء عامل محدد
```

#### 5. في state.py:
```python
current_worker = {"id": worker_id, "name": name}
# الحالة الحالية للعامل النشط
```

## ================================================
# مثال عملي كامل
## ================================================

### السيناريو:

1. **الخطوة 1: المالك يضيف عامل**
   ```
   المالك يكتب: "محمد"
   النظام ينفذ: create_worker("محمد")
   قاعدة البيانات:
   - id: 2 (آلي - بعد علي)
   - name: "محمد"
   - active: 1
   ```

2. **الخطوة 2: محمد يختار وردية**
   ```
   محمد يختار: "وردية ليلية" (schedule_id = 2)
   النظام ينفذ: start_shift_session(2, 2)  # worker_id = 2
   قاعدة البيانات:
   - session_id: 124 (آلي)
   - schedule_id: 2
   - worker_id: 2 (محمد)
   - status: 'active'
   ```

3. **الخطوة 3: محمد يبيع**
   ```
   محمد يبيع: قهوة (8,000 ليرة)
   النظام ينفذ: INSERT receipt (worker_id=2, session_id=124)
   محمد يبيع: كيك (4,000 ليرة)
   النظام ينفذ: INSERT receipt (worker_id=2, session_id=124)
   ```

4. **الخطوة 4: محمد ينهي الوردية**
   ```
   محمد يضغط: "إنهاء الجلسة"
   النظام ينفذ: end_shift_session(124)
   النظام يحسب: التقييم الآلي
   النظام يحفظ: worker_id = 2 في سجل التقييم
   ```

5. **الخطوة 5: محمد يعود للعمل غداً**
   ```
   محمد يختار: "وردية صباحية"
   worker_id = 2 (لا يتغير!)
   session_id = 125 (جديد!)
   ```

## ================================================
# لماذا AUTOINCREMENT مهم؟
## ================================================

### الفوائد:

1. **لا تعارضات**:
   - كل عامل له ID فريد
   - لا يمكن تكرار الأسماء بمعرف ID مختلف

2. **سهولة الربط**:
   - كل فاتورة تُربط بـ worker_id
   - كل جلسة تُربط بـ worker_id
   - سهولة الاستعلام والتحليل

3. **الاستقرار**:
   - ID لا يتغير أبداً
   - حذف عامل لا يغير IDs الآخرين
   - بيانات تاريخية دقيقة

4. **الأتمتة**:
   - لا حاجة لتعيين يدوي
   - لا أخطاء بشرية
   - سريع وفعال

## ================================================
# هل يمكن تعديل worker_id؟
## ================================================

### الجواب: لا، ولا يجب!

**لماذا لا؟**
- worker_id = المفتاح الأساسي (PRIMARY KEY)
- تغييره سيفقد جميع الربطات
- الفواتير ستفقد ربطها بالعامل
- التقييمات ستفقد ربطها
- غير آمن

**ماذا لو أردت تغيير؟**
- لا تغير ID أبداً
- إذا احتجت، احذف العامل وأنشئه مجدداً
- لكن ضع في اعتبارك فقدان البيانات
